# Batch access decision: deferred to NAV13

The minimal public factory/read surface is retained. Each later member/cell read
admits the captured complete source and coherent map independently. This work is
visible in public operation reports and grows when an unrelated sibling grows.
`exactProjectionPUB04ReadCostIncludesUnselectedSource` and the separate 20-case
consumer print deterministic work/node/retention witnesses for 0/16/128 sibling
items. These counters are not busy-host timing or RSS evidence.

A feasible future batch would accept finite representative positions or typed
logical coordinates, admit one original source, validate requests in caller order,
preserve repeated positions, reserve request/result slots before growth, select
all originals under the same exclusive scope, then publish the complete array.
A late invalid coordinate, quota or cancellation must publish no prefix. It needs
a named inclusive request limit, exact output-alias weights and row/column error
precedence. It must not be implemented as repeated calls to public single reads.

The existing P2Accounting.read contract receives a constant-size accessor index
list and returns a single original alias; it does not own a returned aggregate
vector. Extending it would require an additional output-retention contract and
independent compiler, capacity/cancellation and portability proofs, plus a public
coordinate type for matrix batches. No existing qualified result carrier supplies
that proof. This wave therefore does not expose an unqualified aggregate convenience.
B01–B08 are explicitly NOT IMPLEMENTED/DEFERRED, not successful tests. NAV13 should
compare repeated-admission counters and qualify the aggregate contract across all
view families. There is no hidden cache, mutation, nested meter or claim that caller
loops over independent bounded reads provide one cumulative batch budget.
