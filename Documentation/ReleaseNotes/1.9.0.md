# Swift-JSON 1.9.0 — release notes

This minor release adds bounded structural workflows to JSONInspection, one-call
index selection to JSONTransform, and lowers the Apple deployment minimums to
macOS 15 and iOS 18. Preparation and tagging do not establish publication; the
official GitHub release and its qualification asset identify the final source and
actual outcomes.

## Added

**Ordered value batches.** `JSONInspectionBatch` reads typed paths in one
operation. Snapshot ordinals and store positions have matching batch reads. Each
batch uses one cumulative ledger and returns its results atomically. Repeated
requests stay repeated, a missing selection throws, and an explicit JSON null is a
value. `optionalValues(at:maximumRequests:)` returns `nil` for an absent member or
an index past the end, and throws the same errors as `values(at:)` otherwise.

**A read-only configured store.** `JSONStoreBuilder` promotes an immutable source
to `JSONConfiguredStore` after the checked eight-phase construction. Collections,
ID fields, record paths and reference fields are declared explicitly; nothing is
inferred. The store offers exact-ID `lookup(collection:id:)`, ordered value reads
and complete breadth-first `follow(from:)` with finite depth, frontier, visited
and result limits. Positions are owner-bound and cannot be forged or reused
against another build. There is no persistence, mutable store or network
resolution.

- Each collection declares a `JSONStoreIDKind`. String IDs (the default) compare
  by exact decoded Unicode scalars. Integer IDs compare by exact mathematical
  value, so `7`, `7.0` and `7e0` are one ID, and stay exact beyond Double
  precision. IDs never convert between kinds.
- `JSONStoreRecordID` accepts string and integer literals.
- `JSONStoreFailure` is `Equatable` and reports a typed `JSONStoreFailurePhase`
  and, for capacity refusals, a typed `JSONStoreCapacity`.
- `collectionIndex(named:)` maps an exact collection name to its position.
- `JSONStoreReferences.strict(marker:)` always validates reference targets.

**Transform selection.** Versioned Transform source definitions, compile reports
and finite indexed selection scopes over an explicit population, with
owner-bound positions and an EOF completion witness on one invocation ledger.
`JSONTransformProgram.selectIndices(in:bindings:limits:source:)` runs a selection
to the end and returns the ordinals, with the same completion statistics as the
manual loop.

**Composition accounting.** Input bytes are charged per document, completion
charges its own report on the original ledger, and a checked
`reserveExternalLogicalBytes(_:count:overhead:)` overload is added.

## Platforms

The deployment minimums are now **macOS 15 and iOS 18** (previously macOS/iOS 27).
Development still uses Swift 6.4 and the macOS 27 SDK (Xcode 27). Linux and WASI
are unchanged; the WASI lane is pinned to Swift 6.4.2.

- JSONHTML's WebKit `WebPage` PDF backend requires macOS/iOS 26. Earlier systems
  report the existing `JSONPDFFailure.backendUnavailable`.
- Before macOS/iOS 27, the Markdown transfer type uses the system-declared
  `net.daringfireball.markdown` identifier.

Platform evidence is compile-time: every product and test builds at the macOS 15
floor, and every library compiles for `arm64-apple-ios18.0`. No tests have run
on a macOS 15–26 or iOS 18 system.

## Compatibility and qualification

The release is additive over 1.8.0. SwiftPM API-break checking against 1.8.0 reports
one finding, a false positive for a package-only enum, and no public breaking change. The package keeps twelve library products plus `swift-json`, thirteen DocC
catalogs, Swift tools and compiler 6.4+, Swift language mode 6, an empty root
dependency graph, Apache-2.0 and retained upstream notices. CLI metadata reports
`1.9.0` with the deterministic final-source identity.

The maintainer recorded an explicit **exception for the 1.9.0
controlled-performance gate**. It is not a pass. This release makes no speed,
throughput, allocation or RSS claim. Navigation G4 remains HOLD, and earlier
performance dispositions stay historical. Logical retained bytes and caller work
keep their documented accounting boundaries.

The release qualification asset records the actual source-bound Native, Linux,
safety, docs and archive outcomes. See the
[1.9 qualification record](../Qualification/Release1.9.md).
